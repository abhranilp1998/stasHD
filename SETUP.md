# Stashd: setup (M2)

Overview and roadmap: [README.md](README.md) · design: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) · plan: [docs/ROADMAP.md](docs/ROADMAP.md) · history: [CHANGELOG.md](CHANGELOG.md)

Package: `com.abhranil.stashd` · minSdk 26 · targetSdk 35 · compileSdk 36 · JDK 17 · Gradle 8.14.3 · AGP 8.13.2 · Kotlin 2.2.21

The app works **without any Google Cloud setup** in *demo mode*: if no Web client ID is set, Welcome skips sign-in and the browser uses `FakeDriveRepository` (sample albums with nested folders, a resource-keyed folder, an empty folder, a no-access folder and 2-page listings). Demo downloads are real end to end: pick a folder on the phone as destination and "Start download" writes FakeDriveRepository's generated bytes (≈4 MB/s, a few MB per track) through the same downloader, scheduler and notification as real Drive. A Google Doc in the sample is skipped, and a shortcut to an existing track is de-duplicated.

Once `stashd.webClientId` is set (step 3), the real path is used: Sign in with Google → Drive consent (drive.readonly) → `RealDriveRepository` (Drive v3 over OkHttp). To force demo data in a debug build anyway, add `stashd.fakeDrive=true` to `~/.gradle/gradle.properties`.

## 1. Open in Android Studio
1. Unzip `stashd-m0.zip` (or clone the repo) somewhere.
2. Android Studio (Narwhal or newer) → **Open** → select the `stashd/` folder.
3. Settings → Build Tools → Gradle → **Gradle JDK = 17** (the bundled JBR 17/21 works too).
4. SDK Manager: install **Android 15 (API 35)** and **Android 16 (API 36)** platforms. Studio writes `local.properties` with your `sdk.dir` for you.
5. Sync, then run the `app` configuration on your phone (USB debugging on). On Android 13+, allow notifications when asked.

CLI equivalent: `./gradlew assembleDebug` → `app/build/outputs/apk/debug/app-debug.apk`.

## 2. Get YOUR debug SHA-1
Each machine has its own `~/.android/debug.keystore`, so the SHA-1 is different on every machine.
```
./gradlew signingReport      # look at Variant: debug → SHA1
```
For reference, the build box's key (only valid for APKs built on the box) is:
`48:20:53:36:66:33:12:AF:05:A6:ED:EF:6B:EE:F6:41:7F:83:F0:C5`

## 3. Google Cloud (you do this; nothing has been created for you)
1. https://console.cloud.google.com → **New project** (e.g. `stashd`).
2. APIs & Services → Library → **Google Drive API** → Enable.
3. **Google Auth Platform / OAuth consent screen**
   - User type: **External**, publishing status: **Testing**.
   - App name Stashd, your email as support and developer contact.
   - Data access / Scopes → add `https://www.googleapis.com/auth/drive.readonly` (restricted scope; that's fine while in Testing).
   - Audience → **Test users** → add your Google account (up to 100).
   - Note: in Testing, restricted-scope grants **expire after 7 days**. The app will ask for consent again; that's expected.
4. Clients → **Create client → Android**
   - Package name: `com.abhranil.stashd`
   - SHA-1: the value from step 2 (add one Android client per machine/keystore you build from).
5. Clients → **Create client → Web application** (name "Stashd web"). No redirect URIs needed. Copy its **Client ID**. Credential Manager needs this as the `serverClientId`.
6. Put the Web client ID in your **user** Gradle properties (not the repo):
   ```
   # ~/.gradle/gradle.properties   (Windows: %USERPROFILE%\.gradle\gradle.properties)
   stashd.webClientId=1234567890-xxxxxxxx.apps.googleusercontent.com
   ```
7. Rebuild. Welcome → **Sign in with Google** now uses Credential Manager, then asks for Drive read access through AuthorizationClient.

### Download behaviour (M2)
- **One active batch.** A batch is active while preparing, queued, running or paused. "Start download" while one is active shows "Another download is still active…"; finish, cancel, or resume it first.
- **Pause ≠ cancel.** Pause (app, notification, or stopping the job in Android 14's Task Manager) keeps every `.stashdpart` file and its saved offset; Resume continues each file with a Range request after re-checking it hasn't changed on Drive.
- **Cancel policy: delete partials.** Cancel deletes the `.stashdpart` files of unfinished files and marks them cancelled. Files that already finished stay in the destination. Empty folders created for unfinished files may remain.
- **Retries.** 429 and 5xx: up to 5 attempts per file with exponential backoff and jitter (2 s, 4 s, 8 s… capped at 60 s), honouring Retry-After; then the file fails as "retries exhausted" and the batch continues. Network errors: 5 in a row hand the batch back to the scheduler, which re-runs it when the network is back (a file fails after 15 network attempts in total). Checksum mismatch: one full restart, then it fails as "checksum".
- **Terminal per file, with the reason saved:** not found, download disabled (cannotDownloadFile etc.), Google Doc, forbidden.
- **Pauses the whole batch, with the reason saved:** phone storage full, download folder access lost, Google sign-in/consent needed (expired or revoked auth). Fix it and tap Resume. Auth pauses rather than failing every file.
- **System stops** (network lost, Doze, process killed): the batch goes back to queued and resumes from the saved offsets; at most about one second of bytes is re-downloaded.
- Files run one at a time in M2 (the parallelism setting is not used yet).

## 5. First live test once OAuth is set up (M1 acceptance)
1. Install the debug build from **your** machine (its SHA-1 must be on the Android client).
2. Continue with Google → pick your account → allow "See and download your Google Drive files". Try Cancel once: you should get a calm "Drive access is needed…" message, and Continue works again.
3. Paste the music folder link → Open folder. Check the name shows, albums list, tap an album → tracks with sizes.
4. Paste a file link → expect "That's a file link…". Paste a folder you can't access → not-found message.
5. If you have an old link with `?resourcekey=`, open it and a subfolder (exercises the header).
6. Select a file in the root, enter an album, select a track, go back: both stay selected. Then tick "Download this whole folder": the earlier picks fold into it.
6b. Sign out of / switch to a second Google account (if you have one) and open a folder only that account can see.
7. Debug logcat (`OkHttp` tag): `Authorization: ██` and no `ya29.` anywhere.

## 5b. M2 checks on a phone (no Google Cloud needed: demo mode)
1. Android 14+: start a download, lock the phone for a few minutes, unlock: it kept going (UIDT). The job shows in the notification drawer's Task Manager ("Active apps").
2. Pause from the notification, then Resume: progress continues from where it was, not from 0.
3. Turn on airplane mode mid-file: the batch waits; turn it off: it resumes by itself.
4. Swipe the app away from Recents while downloading: the download keeps running (UIDT) or restarts from saved offsets (WorkManager).
5. Cancel mid-file: finished tracks stay, no `.stashdpart` file remains.
6. Pick a folder on an SD card or USB drive as the destination; eject it mid-download → paused ("can't write to the download folder").
7. Android 8–13 (or an emulator): same flow runs through WorkManager with a "Downloading …" foreground notification.
8. Deny the notification permission: the download still runs (Task Manager on 14+), just without progress in the shade.
